**Change 2: Export `handleAuthCallback` as a pure-ish async function**

Following the `resolveBackAction` pattern from `useBackButton.ts`, export a standalone async function (NOT inside the Zustand store):

```typescript
export async function handleAuthCallback(url: string): Promise<void> {
    const parsed = new URL(url);

    if (parsed.pathname === '/auth/callback') {
        const code = parsed.searchParams.get('code');
        if (code && supabase) {
            const { error } = await supabase.auth.exchangeCodeForSession(code);
            if (error) {
                useAuth.setState({ loading: false, error: 'Sign-in failed. Please try again.' });
            } else {
                // onAuthStateChange fires automatically and updates user state
                useAuth.setState({ loading: false });
            }
        } else {
            // No code param — user cancelled or error in OAuth flow
            useAuth.setState({ loading: false, error: null });
        }
        return;
    }

    // Any other focusvalley:// URL is a share link — no routing needed per user decision
    // Main screen is already shown, so this is a no-op
}
```

This function is called from App.tsx's `appUrlOpen` listener and is directly testable from useAuth.test.ts.

**Error message wording (Claude's Discretion):**
- OAuth URL generation failure: use `friendlyError(error)` for Supabase errors, or `'Unable to start sign-in. Please try again.'` for missing URL
- Code exchange failure: `'Sign-in failed. Please try again.'`
- User cancel (no code / browserFinished): reset silently with `error: null`
