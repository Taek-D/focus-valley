  <action>
1. Install @capacitor/browser and sync:
   ```bash
   npm install @capacitor/browser
   npx cap sync android
   ```

2. Update `src/lib/supabase.ts` — add PKCE auth options to `createClient`:
   ```typescript
   export const supabase = isSupabaseConfigured
       ? createClient(SUPABASE_URL!, SUPABASE_ANON_KEY!, {
           auth: {
               flowType: 'pkce',
               detectSessionInUrl: false,
           },
       })
       : null;
   ```
   Keep all existing exports (`SUPABASE_CONFIG_ERROR`, `isSupabaseConfigured`, `supabase`) unchanged.
   Rationale: `flowType: 'pkce'` enables code exchange instead of implicit hash tokens. `detectSessionInUrl: false` prevents race conditions with the manual `exchangeCodeForSession` call in Plan 02 (see Research Pitfall 1). The web OAuth flow still works because `signInWithOAuth` triggers a full page redirect on web — Supabase handles the code exchange on page reload regardless of this setting.

3. Update `android/app/src/main/AndroidManifest.xml` — add a second intent-filter inside the existing `<activity android:name=".MainActivity">` element, as a sibling to the existing MAIN/LAUNCHER intent-filter:
   ```xml
   <intent-filter>
       <action android:name="android.intent.action.VIEW" />
       <category android:name="android.intent.category.DEFAULT" />
       <category android:name="android.intent.category.BROWSABLE" />
       <data android:scheme="focusvalley" />
   </intent-filter>
   ```
   Do NOT add `android:autoVerify="true"` — that is for HTTPS App Links only (per user decision: custom URL scheme only, no App Links).
   Do NOT place the intent-filter outside the `<activity>` element (Research Pitfall 5).
  </action>

  </verify>
